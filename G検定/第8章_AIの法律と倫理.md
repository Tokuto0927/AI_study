# G検定 第8章「AIの法律と倫理」合格ノート

> 参照PDF：:contentReference[oaicite:0]{index=0}  
> 注意：この章は「法律そのものを完璧に覚える章」ではなく、AI活用時にどの法律・倫理論点が問題になるかを選択肢で見抜く章。法律分野は改正があり得るため、本ノートはアップロードPDFの内容に基づくG検定対策用として整理する。

---

## 0. この章のゴール

第8章のゴールは、AIを開発・利用するときに問題になる「法律」と「倫理・ガバナンス」を区別して理解すること。

試験では、以下を問われやすい。

| 覚えるべき軸 | 試験で問われる形 |
|---|---|
| 著作権・特許・個人情報などの法律 | 「これはどの法律の問題か」「何が保護対象か」 |
| AI開発契約・AI利用契約 | 「請負か準委任か」「AIではなぜ性能保証が難しいか」 |
| AI倫理 | 「違法ではないが避けるべきAI利用はどれか」 |
| AIガバナンス | 「企業としてどんな体制・文書・監査・モニタリングが必要か」 |
| 章末問題傾向 | 個人情報の種別、学習済みモデルの著作権、AI開発フェーズ、バイアス、安全性、倫理アセスメント |

この章は、暗記だけだと選択肢で崩れやすい。  
「法律＝守らないと違法になり得るルール」「倫理＝違法でなくても社会的に受け入れられないリスク」「ガバナンス＝それらを組織で管理する仕組み」と整理すると強い。

## 1. 全体像

### 1-1. 第8章の大枠

| 分野 | 内容 | 押さえ方 |
|---|---|---|
| AIの法律 | 著作権法、特許法、不正競争防止法、個人情報保護法、独占禁止法、契約 | 「どの法律が何を守るか」を覚える |
| AI開発契約 | AI開発を委託するときの契約・フェーズ・知財帰属・NDA | AIは性能保証が難しい、準委任が多い |
| AI利用契約 | クラウド型AIなど不特定多数向けAIの利用契約 | 追加学習・入力データ利用・パラメータ変更に注意 |
| AI倫理 | 公平性、安全性、プライバシー、透明性、セキュリティ、悪用防止など | 違法でなくても社会的に問題になる |
| AIガバナンス | AI倫理・リスクを実現するための企業内の仕組み | 経営層、ポリシー、責任者、リスク評価、文書化、監査、改善 |

### 1-2. 法律と倫理とガバナンスの違い

| 用語 | 意味 | 例 | 試験での押さえ方 |
|---|---|---|---|
| 法律 | 国が定めた強制力のあるルール | 個人情報保護法、著作権法 | 違反すると法的責任が生じ得る |
| 倫理 | 法律を守ったうえで、社会的に望ましいかを考える基準 | 採用AIで男女差が出る、顔認識の誤認識 | 違法でなくても批判・停止・信頼低下につながる |
| ガバナンス | 倫理・法律・リスクを組織として管理する仕組み | AIポリシー、責任者、監査、モニタリング | 「企業として継続的に管理する体制」 |

## 2. 重要用語・概念

### 2-1. 法律系の重要用語

| 用語 | 意味 | 試験での押さえ方 | 間違えやすい点 |
|---|---|---|---|
| 著作権 | 著作物を保護する権利。複製権・公衆送信権などの権利の束 | 文章・画像・コードなどの「表現」を守る | アイデア・事実・アルゴリズムそのものは原則として著作権では守られない |
| 著作物 | 思想または感情を創作的に表現したもの | 作者の個性が表れていればよい | 芸術性が高い必要はない |
| 著作者人格権 | 公表権、氏名表示権、同一性保持権など、人格的利益を守る権利 | 譲渡できない | 財産権としての著作権と混同しない |
| 職務著作 | 従業員が職務上作成した著作物について、一定要件で会社に著作権が帰属する制度 | 従業員作成なら会社帰属になり得る | 業務委託先が作ったものは、当然に発注者へ帰属するわけではない |
| 著作権法30条の4 | 情報解析などのための著作物利用を一定範囲で認める規定 | AI学習用データ利用で頻出 | 学習に使えるからといって、生成物の権利侵害が必ず許されるわけではない |
| 特許権 | アイデア・発明を保護する権利 | 自然法則を利用した発明、新規性、進歩性などが必要 | 著作権と違い、出願・審査・登録が必要 |
| 営業秘密 | 秘密管理性・有用性・非公知性を満たす情報 | データ・ノウハウ保護で重要 | 会社が「秘密だと思っている」だけでは足りない |
| 限定提供データ | 事業として一定条件で提供される相当量の電子データ | ビッグデータ提供を保護する制度 | 営業秘密に該当する場合は限定提供データではない |
| 個人情報 | 生存する個人に関する情報で、特定個人を識別できるもの、または個人識別符号を含むもの | 氏名、顔写真、容易照合できるID付きデータなど | 電話番号や位置情報は単体では個人情報でない場合があるが、氏名などと結び付くと個人情報になり得る |
| 個人データ | 個人データベース等を構成する個人情報 | 第三者提供・安全管理義務で重要 | 個人情報より規制が強くなる |
| 保有個人データ | 事業者が開示・訂正・削除などの権限を持つ個人データ | 本人から開示・訂正等の請求対象 | 委託で預かっているだけのデータは保有個人データではない |
| 要配慮個人情報 | 人種、信条、病歴、犯罪歴など特にセンシティブな個人情報 | 原則、取得に本人同意が必要 | オプトアウトによる第三者提供はできない |
| 匿名加工情報 | 特定個人を識別できず、復元できないよう加工した情報 | 一定事項の公表により同意なく第三者提供可能 | 氏名削除だけでは足りないことがある |
| 仮名加工情報 | 他情報と照合しない限り個人を識別できないよう加工した情報 | 主に事業者内部での利活用を想定 | 匿名加工情報より匿名化の度合いが低く、第三者提供は原則禁止 |
| 個人関連情報 | 個人情報・仮名加工情報・匿名加工情報のいずれにも該当しない、生存する個人に関する情報 | IPアドレス、閲覧履歴、購買履歴など | 個人識別符号とは違う。提供先で個人データ化される場合は同意確認が必要 |
| GDPR | EUの個人データ保護規則 | EU向けサービスやEU域内個人の監視でも適用され得る | 日本企業にも関係し得る |
| 独占禁止法 | 公正かつ自由な競争を守る法律 | データ囲い込み、AIカルテルで出題され得る | AIそのものを禁止する法律ではない |
| 請負契約 | 仕事の完成を約束する契約 | 完成義務・契約不適合責任が問題 | AI開発では成果保証が難しいため常に適切とは限らない |
| 準委任契約 | 事務処理・業務の遂行を約束する契約 | AI開発で多く使われる | 完成を約束する契約ではない |
| NDA | 秘密保持契約 | 目的外利用禁止、秘密情報の保護、守秘期間が重要 | 締結すれば何にでも使えるわけではない |

### 2-2. AI倫理・ガバナンス系の重要用語

| 用語 | 意味 | 試験での押さえ方 | 間違えやすい点 |
|---|---|---|---|
| AI倫理 | AIによる望ましくない社会的影響を避けるための考え方 | 法律遵守に加えて守るべき社会的正しさ | 「違法でなければOK」ではない |
| Trustworthy AI | 信頼できるAI | AI倫理と近い意味 | 技術精度だけでなく、公平性・安全性・透明性なども含む |
| Responsible AI | 責任あるAI | AI倫理・説明責任・運用責任の文脈 | 単に高精度なAIという意味ではない |
| AIガバナンス | AI倫理上の課題に対応するため、企業が行う仕組み | ポリシー、責任者、リスク評価、監査、教育など | 倫理の理念そのものではなく、実現するための組織的取組み |
| ハード・ロー | 法律など、遵守義務のあるルール | 法的強制力あり | 変更が遅い、柔軟性が低い |
| ソフト・ロー | ガイドライン、自主規制など | 法的強制力は弱いが実務上重要 | 法的強制力がないから無視してよい、は誤り |
| 公平性 | AIの出力が不当な差別・偏りを生まないこと | 採用AI、顔認識で頻出 | 精度が高くても公平とは限らない |
| バイアス | データ・人間判断・アノテーションなどに入り込む偏り | 基本的にはデータ由来が多い | アルゴリズムだけが原因ではない |
| センシティヴ属性 | 性別、人種、肌の色など、差別や不公平に関わる属性 | 何を問題属性にするかは人間が判断する | 統計的手法で完全自動選定できる、は誤り |
| 安全性 | AIにより生命・身体・財産へ危害が及ばないよう配慮すること | 医療・自動運転・産業利用で重要 | 精度が高い＝常に安全、ではない |
| 有効性 | AIがタスクに対して適切に判断できること | 安全性とは別概念 | 精度と安全性はトレードオフになることがある |
| プライバシー・バイ・デザイン | 設計段階からプライバシー保護を組み込む考え方 | 事後対応ではなく初期設計から考える | 個人情報保護法だけ守れば十分とは限らない |
| 透明性 | AI利用や判断根拠、目的、責任者、影響などを開示すること | 「何を、誰に、なぜ開示するか」が重要 | すべての内部構造を公開することではない |
| アカウンタビリティ | AIに関する責任を負うこと、説明・追跡・検証できる状態にすること | 責任者、文書化、追跡可能性、検証可能性 | 単なる説明のうまさではない |
| データ汚染攻撃 | 学習用データを汚染してAIの挙動を悪化・操作する攻撃 | AI固有のセキュリティ論点 | 通常の情報漏洩対策だけでは不十分 |
| 敵対的事例 | 入力に細工してAIの推論結果を誤らせるもの | Adversarial example | 人間にはほぼ同じに見えてもAIだけ誤ることがある |
| モデル汚染攻撃 | 細工したモデルを配布するなどしてAIを害する攻撃 | AIモデル自体が攻撃対象 | データだけでなくモデルも守る |
| フェールセーフ | 異常時でも安全側に倒れる設計 | 安全性確保策として頻出 | 事故後だけでなく事前設計が重要 |
| モニタリング | 運用後に性能・リスク・挙動を継続監視すること | デプロイ後も終わりではない | AIは環境変化で性能劣化する |
| ステークホルダー関与 | 利用者、影響を受ける人、専門家など多様な関係者を巻き込むこと | リスクを多角的に見る | 開発当初に決めた範囲を固定する、は誤り |

## 3. 重要論点の整理

### 3-1. 著作権法：表現を守る。アイデア・事実は原則守らない

| 論点 | 正しい理解 | 試験で狙われるポイント |
|---|---|---|
| 著作権の対象 | 思想・感情の創作的表現 | 表現であることが必要 |
| 事実・データ | 原則として著作権の対象ではない | ニュースの事実自体、客観データ自体は保護されにくい |
| アルゴリズム・数学的手法 | アイデアなので著作権の対象外 | Dropoutの手法そのものは著作権で守られない |
| プログラムコード | 著作物になり得る | コードをコピーすると著作権侵害になり得る |
| パラメータ | 計算結果の数値列 | 原則として著作権は発生しない |
| データベース | 情報の選択・体系的構成に創作性があれば著作権が認められる場合あり | 個々のデータではなく、データベース構成がポイント |
| AI学習用データ | 著作物のコピー等は30条の4により原則適法と整理される | ただし生成物の侵害問題とは別 |
| AI生成物 | AIだけが生成したものは人間の創作性がないため著作権は成立しない | 人間の創作的寄与があれば著作権成立の可能性あり |

#### 著作権での超重要区別

| 比較 | A | B |
|---|---|---|
| 所有権 vs 著作権 | 本そのものを持つ権利 | 本の文章という情報・表現に関する権利 |
| 著作権 vs 著作者人格権 | 財産的権利。譲渡可能 | 人格的権利。譲渡不可 |
| アイデア vs 表現 | 著作権では原則守られない | 著作権で守られる |
| 学習用データ利用 vs 生成物侵害 | 原則適法になり得る | 既存著作物との類似・依拠性が問題 |

### 3-2. 特許法：アイデア・発明を守る。ただし登録が必要

| 論点 | 内容 |
|---|---|
| 保護対象 | アイデア、発明 |
| 主な要件 | 自然法則の利用、産業上利用可能性、新規性、進歩性 |
| 権利発生 | 特許庁への出願、審査、登録が必要 |
| 先願主義 | 同一発明なら先に出願した者が優先 |
| 職務発明 | 従業員が職務上行った発明は、契約・就業規則などにより会社帰属になり得る。ただし相当の対価が必要 |

#### 著作権との違い

| 観点 | 著作権 | 特許権 |
|---|---|---|
| 守るもの | 表現 | アイデア・発明 |
| 発生方法 | 創作により自動発生 | 出願・審査・登録が必要 |
| 例 | 文章、画像、コード | 技術的アイデア、発明 |
| 試験の引っかけ | アイデアを著作権で守る、とする選択肢 | 登録不要で特許権が発生する、とする選択肢 |

### 3-3. データ保護と不正競争防止法

| 用語 | 要件・特徴 | 試験ポイント |
|---|---|---|
| 営業秘密 | 秘密管理性、有用性、非公知性 | 秘密管理措置が必要 |
| 限定提供データ | 事業として提供、相当量蓄積、電子データなど | ビッグデータ提供を保護する制度 |
| 不正競争行為 | 窃取、不正取得、不正利用など | 営業秘密・限定提供データの侵害で問題 |

#### 営業秘密の秘密管理性で問われる例

| 秘密管理性ありに近い例 | 秘密管理性が弱い例 |
|---|---|
| 「マル秘」表記がある | 会社が心の中で秘密と思っているだけ |
| アクセス制限・パスワード設定 | 誰でも見られる共有フォルダ |
| 営業秘密リストで管理 | 一般資料と混在している |
| 他情報と区別して保存 | 区別されていない |

### 3-4. 個人情報保護法：分類を正確に覚える

#### 基本関係

| 種別 | 意味 | 規制のイメージ |
|---|---|---|
| 個人情報 | 特定個人を識別できる情報、または個人識別符号を含む情報 | 利用目的の特定・通知・公表など |
| 個人データ | 個人データベース等を構成する個人情報 | 安全管理義務、第三者提供規制 |
| 保有個人データ | 事業者が開示・訂正・削除等の権限を持つ個人データ | 本人からの開示・訂正等の請求対象 |

関係は以下。

| 包含関係 |
|---|
| 個人情報 ⊃ 個人データ ⊃ 保有個人データ |

#### 個人情報に当たりやすいもの・当たりにくいもの

| 情報 | 個人情報に該当するか | 理由 |
|---|---|---|
| 氏名 | 該当しやすい | 個人を識別できる |
| 顔写真 | 該当しやすい | 個人を識別できる |
| 氏名付きメールアドレス | 該当しやすい | 個人を識別できる場合がある |
| 電話番号単体 | 該当しない場合がある | 単体では誰の番号か特定できない場合がある |
| 位置情報単体 | 該当しない場合がある | 単体では個人を識別できない場合がある |
| ID＋購買履歴 | 元データと容易に照合できれば該当 | 容易照合性がある |
| 顔認識特徴ベクトル | 該当し得る | 生体情報として個人識別符号に該当し得る |

#### 特殊類型

| 種別 | 意味 | 第三者提供・利用の注意 |
|---|---|---|
| 要配慮個人情報 | 人種、信条、病歴、犯罪歴などセンシティブな個人情報 | 原則、取得に本人同意が必要。オプトアウト提供不可 |
| 匿名加工情報 | 個人を識別できず復元もできないよう加工した情報 | 一定事項を公表すれば同意なく第三者提供可能 |
| 仮名加工情報 | 他情報と照合しない限り個人識別できないよう加工した情報 | 原則、第三者提供禁止。内部利用向け |
| 個人関連情報 | 個人情報等には当たらないが、生存する個人に関する情報 | 提供先で個人データ化される場合、本人同意取得の確認が必要 |

#### 匿名加工情報と仮名加工情報の違い

| 観点 | 匿名加工情報 | 仮名加工情報 |
|---|---|---|
| 匿名化の強さ | 強い | 匿名加工情報より弱い |
| 復元可能性 | 個人識別・復元ができないよう加工 | 他情報と照合すれば識別できる可能性あり |
| 主な利用目的 | 比較的自由な利活用・第三者提供 | 事業者内部での分析・利活用 |
| 第三者提供 | 一定条件で可能 | 原則禁止 |
| 例 | 氏名削除、住所を市町村レベルに抽象化、ID削除、特異値削除など | 氏名・クレカ番号などを削除。ただし特異値削除までは不要な場合あり |

### 3-5. 独占禁止法：AI・データで競争を阻害しない

| 論点 | 内容 | 試験での押さえ方 |
|---|---|---|
| 独占禁止法 | 自由競争を阻害する行為を禁止する法律 | 公正・自由な競争と消費者利益を守る |
| データ囲い込み | 市場支配力のある企業が不可欠なデータへのアクセスを不当に拒む問題 | データが競争上不可欠な場合に問題化 |
| AIカルテル | AI・アルゴリズムを用いて価格協調・カルテルを行う問題 | AIが価格監視や協調価格設定に使われると問題 |
| デジタルプラットフォーム規制 | 透明性・公平性を高めるための規制 | 取引条件の開示、運営状況の報告など |

### 3-6. AI開発契約：AIは「完成保証」が難しい

#### 請負と準委任

| 観点 | 請負契約 | 準委任契約 |
|---|---|---|
| 約束するもの | 仕事の完成 | 事務処理・業務の遂行 |
| 報酬 | 完成結果に対して支払う | 業務遂行や成果に応じて支払う |
| 契約不適合責任 | 問題になり得る | 原則適用されない |
| AI開発との相性 | 性能保証が難しいため注意 | AI開発で多く用いられる |
| 例 | 仕様通りの建物を建てる | 医師が診療・手術を行う |

#### AI開発契約の特徴

| 特徴 | 理由 |
|---|---|
| モデル性能がデータ品質に依存する | 学習用データが悪いとモデルも悪くなる |
| 性能保証が難しい | 契約時点で未知データへの性能を予測しにくい |
| ノウハウが重要 | 前処理、特徴量、ハイパーパラメータ、ドメイン知識などが効く |
| 知財帰属を契約で決める必要 | コード、データセット、モデル、パラメータなどの扱いが問題になる |
| NDAが重要 | 学習データ、業務データ、ノウハウが相手方に渡るため |

#### AI開発フェーズ

| フェーズ | 内容 | 契約上の押さえ方 |
|---|---|---|
| アセスメント | 課題整理、AI以外の方法の有無、AIが有効か検討 | 報告書が成果物。準委任が多い |
| PoC | 実運用可能なモデルが作れるか、精度向上や課題解決を検証 | 調査目的。準委任が多い |
| 実装・本開発 | 実運用のためのAIを作成 | 予測困難なので準委任が多い。成果完成型準委任もあり得る |
| 保守・運用 | デプロイ後の運用 | モニタリング・改善が必要 |
| 追加学習 | 追加データでモデルを再学習 | 準委任が一般的 |

#### 章末問題での重要ポイント

| 問われ方 | 正解の考え方 |
|---|---|
| 「開発段階ではベンダーが期待精度を保証する責任がある」 | 不適切。AIの精度はデータに依存し、事前保証が難しい |
| 「追加学習は納品済みモデルに追加データで学習する段階」 | 適切 |
| 「アセスメントは生成可能性を事前検証する段階」 | 適切 |
| 「PoCは生成・精度向上作業を行い、事後開発の可否を検証する段階」 | 適切 |

### 3-7. AI利用契約：クラウド型AIは追加学習に注意

| 論点 | 内容 | 試験ポイント |
|---|---|---|
| AI利用契約 | クラウド型AIのように不特定多数ユーザーへ提供されるAIの契約 | 専用開発契約とは違う |
| 追加学習 | サービス提供者側の判断でモデルが更新され得る | 昨日と同じ入力でも出力が変わる可能性 |
| 精度低下 | ユーザー環境で性能が変わることがある | 契約で説明・責任範囲を定める |
| 入力データの利用 | ユーザー入力を追加学習に使う場合がある | 利用契約に明記すべき |

### 3-8. AI倫理：法律違反でなくても問題になる

| 倫理論点 | 例 | 対応 |
|---|---|---|
| 公平性 | 採用AIが男性を優遇、顔認識の肌色差 | バイアス評価、センシティヴ属性の検討、残存バイアスの説明 |
| 安全性 | 医療AIの見逃し、自動運転事故 | フェールセーフ、基準遵守、人間の関与、事故時対応 |
| プライバシー | 監視カメラ、センシティヴ情報の推論 | プライバシー・バイ・デザイン、利用目的・保存方法・周知 |
| 透明性 | AI利用を知らせない、判断理由不明 | AI利用、目的、根拠、責任者、影響の開示 |
| アカウンタビリティ | 誰が責任を持つか不明 | 責任者、追跡可能性、文書化、検証可能性 |
| セキュリティ | データ汚染攻撃、敵対的事例、モデル汚染 | AI固有の攻撃対策 |
| 悪用防止 | ディープフェイク、詐欺、危険物情報、サイバー攻撃 | 利用制限、監視、出力制御 |
| 仕事の保護 | AI自動化による雇用喪失 | 影響最小化、リスキリング、AIと人間の協働 |
| 民主主義 | 誤情報、選挙介入、フィルターバブル | 誤情報対策、推薦の偏り対策 |
| 環境 | AIの電力消費 | 環境影響への配慮 |
| 生成AI特有の問題 | 誤情報、バイアス再生、不適切表現、機密漏洩 | コンテンツ安全性、プライバシー・機密保護 |

### 3-9. バイアスと公平性

| 論点 | 内容 |
|---|---|
| バイアスの原因 | 基本的にはデータに由来することが多い |
| 入り込む段階 | データ生成、収集、アノテーション、前処理など |
| センシティヴ属性 | 性別、人種、肌の色など、差別と関係する属性 |
| 対応の難しさ | 何を問題あるバイアスとするかはドメイン・国・文化・年齢層によって変わる |
| 精度との関係 | バイアス低減と精度確保がトレードオフになる場合がある |
| 残存バイアス | 完全排除できない場合、利用者や分析対象者に情報共有することが望ましい |

#### 章末問題ポイント

| 選択肢の形 | 判断 |
|---|---|
| センシティヴ属性の選定は統計的手法で自動化され実運用されつつある | 不適切 |
| センシティヴ属性の選定は人間の判断が必要 | 適切 |
| 既存バイアスをAIが再生産する可能性がある | 適切 |
| バイアス低減と精度はトレードオフになることがある | 適切 |
| 残存バイアスは利用者等に共有することが望ましい | 適切 |

### 3-10. 安全性と有効性

| 用語 | 意味 | 例 |
|---|---|---|
| 安全性 | AIにより生命・身体・財産に危害が及ばないようにすること | 医療AIでがんを見逃さない |
| 有効性 | AIがタスクに対して適切に判断できること | 分類精度が高い |

注意点は「精度が高い＝安全」とは限らないこと。

| 医療AIの例 | 安全性の観点 |
|---|---|
| がんではない人をがんと判定 | 不安や追加検査の問題 |
| がんの人を健康と判定 | 治療機会を失うため重大 |
| 全体精度を下げても、がん見逃しを避ける | 安全性重視としてあり得る |

#### 安全性確保策

| 対策 | 内容 |
|---|---|
| 安全性基準の遵守 | ドメインに基準があれば従う |
| フェールセーフ | 想定外動作でも安全側に倒す |
| 注意喚起・情報開示 | 人間がAIを過信しないようにする |
| 初動措置の整理 | 事故発生時の対応を事前に決める |
| 原因調査 | 重大事故後に調査委員会等で原因を調べる |
| ユーザー点検 | 提供者だけでなく、現場ユーザーの点検が必要な場合もある |

### 3-11. 透明性とアカウンタビリティ

| 用語 | 何を意味するか | 具体例 |
|---|---|---|
| 透明性 | 情報の開示 | AIを利用していること、判断根拠、目的、適切な利用方法、責任者、影響 |
| アカウンタビリティ | AIに関して責任を負うこと | 追跡可能性、検証可能性、文書化、責任者・担当組織の明確化 |
| データ来歴 | データがどう生成・処理されたか | データ品質や説明可能性のために重要 |

#### 引っかけ

| 誤りやすい理解 | 正しい理解 |
|---|---|
| 透明性＝モデルの中身を全部公開すること | 目的・相手・理由に応じて必要情報を開示すること |
| アカウンタビリティ＝説明文を書くこと | 責任者、追跡、検証、文書化まで含む |
| AIはブラックボックスだから透明性は不要 | ブラックボックスだからこそ透明性が求められる |

### 3-12. AIガバナンス

AIガバナンスは「AI倫理を企業の中で実現する仕組み」。

| 項目 | 内容 | 試験での押さえ方 |
|---|---|---|
| 経営層の関与 | 組織としてAIガバナンスに取り組む意思決定 | 現場任せでは不十分 |
| AIポリシー | AIに関する価値・原則・取組方針を文書化 | プライバシーポリシーに近い |
| 責任者の特定 | 実施責任者・担当組織を決める | 誰が責任を持つか明確化 |
| AIリスク・アセスメント | AIが組織・利用者・社会に与えるリスクを検討 | 可能性と被害の大きさで評価 |
| 目標・手続の設定 | 精度等の目標や手続を決める | 測定可能な目標に限らない |
| 社内教育 | 関係従業員への教育 | 運用者も含む |
| 文書化 | 必要文書を保存しアクセス可能にする | 後から説明・監査できるようにする |
| モニタリング | デプロイ後の継続監視 | AIは運用後も変化・劣化する |
| 内部監査 | ルール遵守状況を確認 | 監査後の改善まで必要 |
| 振り返りと改善 | 結果に基づいて改善 | 一度作って終わりではない |

#### リスク低減措置

| 措置 | 内容 | 注意点 |
|---|---|---|
| 人間の関与 | AI出力を人間が確認・最終判断する | 人間が正しいAI判断を修正して精度を下げる場合もある |
| フィードバック | ユーザー・社会からの意見を収集し改善につなげる | 事前に全リスクを予測できないため重要 |
| ステークホルダー関与 | 多様な関係者を巻き込む | 開発が進むと範囲が変わり得る |
| 多様性の確保 | チームや関係者の専門性・属性の多様性を確保 | 偏った視点を避ける |
| データ品質確保 | データの品質・来歴を把握する | AI品質と倫理の両方に関係 |

## 4. 似た用語の違い

### 4-1. 法律系

| 似た用語 | 違い |
|---|---|
| 著作権と所有権 | 所有権は物への権利。著作権は表現・情報への権利 |
| 著作権と特許権 | 著作権は表現。特許権は発明・アイデア |
| 著作権と著作者人格権 | 著作権は財産権で譲渡可能。著作者人格権は人格的権利で譲渡不可 |
| 職務著作と業務委託 | 職務著作は従業員が対象。業務委託先の著作権は当然に発注者へ移らない |
| 営業秘密と限定提供データ | 営業秘密は秘密管理性が必要。限定提供データは第三者提供されるビッグデータ等を想定 |
| 個人情報と個人関連情報 | 個人情報は特定個人を識別可能。個人関連情報は個人に関するが単体では識別できない情報 |
| 匿名加工情報と仮名加工情報 | 匿名加工情報は識別・復元不能を目指す。仮名加工情報は内部利用向けで第三者提供は原則禁止 |
| 請負と準委任 | 請負は完成義務。準委任は業務遂行義務 |
| AI開発契約とAI利用契約 | AI開発契約は専用AIの開発委託。AI利用契約はクラウド型AI等の利用 |

### 4-2. 倫理・ガバナンス系

| 似た用語 | 違い |
|---|---|
| AI倫理とAIガバナンス | 倫理は守るべき価値。ガバナンスはそれを実現する仕組み |
| 安全性と有効性 | 安全性は危害防止。有効性はタスク達成能力 |
| 透明性と説明可能性 | 透明性は情報開示全般。説明可能性は判断根拠を説明できること |
| 透明性とアカウンタビリティ | 透明性は開示。アカウンタビリティは責任・追跡・検証・文書化 |
| ハード・ローとソフト・ロー | ハード・ローは法律で強制力あり。ソフト・ローはガイドライン等で柔軟だが実務上重要 |
| セキュリティとプライバシー | セキュリティは攻撃・漏洩等から守る。プライバシーは個人情報や自己情報コントロールの尊重 |

## 5. 試験で狙われる引っかけ

| 引っかけ選択肢 | なぜ誤りか |
|---|---|
| AIを直接規制する法律が日本に包括的に存在する | PDFでは、AI自体を直接規制する法律は存在しない前提で、既存法を扱う |
| 著作権はアイデアを保護する | 著作権は表現を保護する。アイデアは特許の領域 |
| アルゴリズムや数学的手法は著作権で保護される | 原則、アイデア・手法であり著作権の対象外 |
| パラメータには著作権が発生する | パラメータは計算結果の数値列であり、原則著作権は発生しない |
| AI生成物は常に著作権で保護される | AI単独生成物は人間の創作性がないため、著作権が成立しない |
| AI学習に著作物を使えるなら、生成物が既存著作物に似ていても必ず合法 | 学習利用と生成物の権利侵害は別問題 |
| 業務委託先が作成した著作物は当然に発注者のもの | 契約で定めなければ、業務委託先に帰属するのが基本 |
| 特許権は創作した瞬間に発生する | 出願・審査・登録が必要 |
| 営業秘密は会社が秘密と思えば成立する | 秘密管理性、有用性、非公知性が必要 |
| IPアドレスやCookieは個人識別符号である | 個人関連情報にはなり得るが、個人識別符号とは限らない |
| 匿名加工情報は他情報と照合すれば個人識別可能 | 匿名加工情報は特定個人を識別できず、復元できないよう加工する |
| 仮名加工情報は第三者提供向けの制度 | 原則、第三者提供は禁止。内部利用向け |
| AI開発ではベンダーが期待精度を保証すべき | AI性能はデータ依存で事前保証が難しい |
| AI倫理は法律を守っていれば不要 | 違法でなくても社会的批判・利用停止・品質低下につながる |
| センシティヴ属性の選定は統計的に自動化できる | 何をセンシティヴとするかは人間の判断が必要 |
| AIの安全対策は提供者だけが行えばよい | 現場ユーザーによる点検が必要な場合もある |
| ステークホルダー範囲は開発初期に固定すべき | 開発進行に応じて変化し得る |
| 透明性とはAIモデルの中身を全部公開すること | 誰に、何を、なぜ開示するかを検討すること |
| AIガバナンスはAIポリシーを作れば終わり | 教育、文書化、監査、モニタリング、改善まで必要 |

## 8. 最重要暗記セット

### 8-1. 法律

| 暗記項目 | 覚え方 |
|---|---|
| 著作権は表現を守る | アイデア・事実・データそのものは原則対象外 |
| 特許権は発明・アイデアを守る | 出願・審査・登録が必要 |
| プログラムコードは著作物になり得る | コードをコピーすると侵害リスク |
| パラメータは著作物ではない | 計算結果の数値列 |
| AI単独生成物は著作権が成立しない | 人間の創作的寄与があれば別 |
| 職務著作は従業員が対象 | 業務委託先の著作権は当然に発注者へ移らない |
| 営業秘密の3要件 | 秘密管理性・有用性・非公知性 |
| 個人情報の関係 | 個人情報 ⊃ 個人データ ⊃ 保有個人データ |
| 要配慮個人情報 | 原則、取得に本人同意。オプトアウト提供不可 |
| 匿名加工情報 | 識別・復元不能。一定条件で第三者提供可 |
| 仮名加工情報 | 内部利用向け。第三者提供は原則禁止 |
| 個人関連情報 | IPアドレス、閲覧履歴、購買履歴など |
| AI開発契約 | 性能保証が難しく、準委任が多い |
| NDA | 秘密保持だけでなく目的外利用禁止が重要 |

### 8-2. 倫理・ガバナンス

| 暗記項目 | 覚え方 |
|---|---|
| AI倫理 | 法律遵守＋社会的に正しいAI |
| AIガバナンス | 倫理を組織で実現する仕組み |
| ハード・ロー | 法律。強制力あり |
| ソフト・ロー | ガイドライン。強制力は弱いが実務上重要 |
| 公平性 | バイアス・差別を防ぐ |
| バイアス原因 | データ生成・収集・アノテーション・前処理など |
| センシティヴ属性 | 人間が判断して選ぶ |
| 安全性 | 生命・身体・財産への危害防止 |
| 有効性 | タスクを適切に判断できること |
| 透明性 | AI利用、目的、根拠、責任者、影響などの開示 |
| アカウンタビリティ | 責任、追跡可能性、検証可能性、文書化 |
| セキュリティ | データ汚染攻撃、敵対的事例、モデル汚染 |
| 生成AIリスク | 誤情報、バイアス、不適切表現、機密漏洩 |
| AIガバナンス施策 | 経営層、AIポリシー、責任者、リスク評価、教育、文書化、モニタリング、監査、改善 |

## 10. 最短復習用まとめ

### 10-1. 30秒復習

第8章は「AIを社会で使うときの法律・倫理・ガバナンス」の章。

- 著作権：表現を守る。アイデア・事実・パラメータは原則対象外。
- 特許権：発明・アイデアを守る。登録が必要。
- 個人情報：個人情報 ⊃ 個人データ ⊃ 保有個人データ。
- 匿名加工情報：識別・復元不能。第三者提供しやすい。
- 仮名加工情報：内部利用向け。第三者提供は原則禁止。
- 個人関連情報：IP、閲覧履歴、購買履歴など。提供先で個人データ化される場合は注意。
- AI開発契約：性能はデータ依存なので保証が難しい。準委任が多い。
- AI倫理：違法でなくても、不公平・危険・不透明・プライバシー侵害なら問題。
- AIガバナンス：経営層、ポリシー、責任者、リスク評価、教育、文書化、モニタリング、監査、改善。

### 10-2. 1分復習表

| 分野 | 一言で |
|---|---|
| 著作権 | 表現を守る |
| 特許権 | 発明を守る |

### 10-3. 試験直前チェック

- 著作権は「表現」、特許は「アイデア」。
- AIパラメータに著作権は原則ない。
- AI単独生成物に著作権は原則ない。
- 業務委託先の著作物は当然に発注者へ帰属しない。
- 営業秘密は「秘密管理性・有用性・非公知性」。
- 個人情報、個人データ、保有個人データの包含関係を覚える。
- 匿名加工情報と仮名加工情報の違いを覚える。
- 個人関連情報はIP・閲覧履歴・購買履歴など。
- AI開発では精度保証が難しい。
- センシティヴ属性の選定は人間の判断。
- AI安全性は提供者だけでなくユーザー点検も必要な場合あり。
- ステークホルダー範囲は開発進行で変わり得る。
- AIガバナンスは「作って終わり」ではなく、運用後の監視・監査・改善まで。
